# Phase 1 — CIL CFG dataflow, SSA/phi and reducible loops

## Gate

Phase 0 has frozen the exact scalar semantics, branch/comparison admission policy,
budgets and every target fact required by the importer.

## Goal

Replace the current restricted linear/value-only assumptions with a bounded
predecessor-sensitive method-local dataflow importer. Forward/backward branches,
reducible loops and loop-carried scalar values must be correctness features of the CFG
and SSA model, not incidental opcode extensions.

## Required pipeline

Implement and verify this logical order:

```text
CIL decode with exact offsets
-> leader/basic-block discovery
-> explicit successors/predecessors and terminators
-> CFG verifier
-> per-block eval-stack/local abstract-state worklist to fixpoint
-> typed merge semantics
-> SSA/value identity + phi construction
-> dominance/backedge/reducibility/loop discovery
-> critical-edge handling
-> edge-specific virtual parallel-copy phi lowering
-> CFG/value-flow re-verification + fact invalidation
```

## CFG requirements

- Stable block IDs and deterministic block traversal independent of hash order.
- Reciprocal predecessor/successor sets.
- Exact target-boundary validation.
- Explicit terminators, fall-through semantics and multiple-return support.
- Defined reachable/unreachable-block policy.
- Backedges allowed only after stack/local state is proven compatible.
- Irreducible control flow rejected deterministically in V1.
- EH-associated control flow remains rejected.

## Abstract-state fixpoint

For every block entry compute at least:

`StackHeight + StackSlotTypes + LocalValueState + ArgumentValueState`.

At a join:

- stack heights must match;
- corresponding slots must have exactly compatible admitted scalar semantics;
- locals/stack values arriving from different predecessors produce explicit merge/phi
  facts;
- incompatible/unverifiable joins fail closed;
- PE `maxstack` is only a bound, not proof that stack flow is valid.

Remove the current architectural restrictions that substitute for real dataflow (for
example one-write locals, backward-branch prohibition or mandatory empty stack at every
leader) only when the new verifier/fixpoint provides equivalent or stronger evidence.

## SSA/phi correctness

Phi/merge state must be a first-class correctness fact until destruction. The chosen IR
representation may be Canonical `Phi`/`ParallelCopy` pseudo-operations or a dedicated
SSA layer, but one authoritative representation and verifier must exist.

Required properties:

- every phi incoming edge maps to exactly one CFG predecessor;
- loop-carried values are represented by backedge incoming values;
- simultaneous phi assignments have parallel-copy semantics;
- copy cycles such as `{a <- b, b <- a}` are broken with explicit temporary values;
- temporaries participate in liveness/pressure/allocation;
- critical edges are split or represented by an equivalent edge-local copy mechanism;
- naive predecessor-end copies on a critical edge are forbidden.

## Loops

Semantic loop support requires:

- dominance/backedge detection;
- reducibility/natural-loop facts;
- deterministic loop-forest ordering;
- loop-carried induction/accumulator values;
- nested-loop handling within budgets;
- ordinary correct scheduling when modulo scheduling is unavailable.

MII, dependency-distance and modulo scheduling remain Core optimizations. Failure to
modulo-schedule a semantically valid admitted loop must not by itself reject the program
unless the profile explicitly promises only a modulo-scheduled subset.

`break`, `continue` and multiple loop exits are not advertised solely because arbitrary
branches exist. Each becomes `Guaranteed` only after exact CIL admission and ISE
execution tests; otherwise it remains conditional or fail-closed according to the
Phase 0 support matrix.

## CIL shape qualification

Freeze a corpus generated by the supported Roslyn/.NET SDK version. Qualify at least
Debug/Release shapes where they differ for:

- nested `if/else`;
- `for`;
- `while`;
- `do/while`;
- nested loops;
- loop-carried induction and accumulator locals;
- conditional loop exits.

The importer must admit exact required branch/comparison opcode forms instead of
assuming high-level constructs lower to already-supported instructions.

## Invalidation barrier

Critical-edge splitting, phi destruction and copy insertion invalidate affected CFG,
dominance/loop, defs/uses, dependency, liveness, pressure, resource, MII/distance,
schedule and bundle/placement facts. Stale consumers must be rejected by analysis
versions/generations or an equally strict pass-manager contract.

## Tests

Positive/semantic:

- forward diamond and nested diamond with scalar merges;
- backward branch with valid block-state merge;
- induction variable and accumulator carried through a backedge;
- two simultaneous phi values;
- critical-edge phi;
- parallel-copy cycle;
- `for`, `while`, `do/while`, zero/one/many iterations;
- nested reducible loops;
- loop with conditional exit.

Negative:

- malformed branch target;
- mismatched stack height;
- incompatible stack/local scalar type merge;
- irreducible two-entry loop;
- unsupported reference local;
- phi/block/edge/loop budget overflow;
- unsupported opcode/comparison shape.

Property/determinism:

- predecessor/successor reciprocity;
- stable block/phi/loop order under shuffled discovery;
- SSA verifier rejects missing/extra incoming values;
- compute facts -> mutate CFG/copies -> stale fact cannot be consumed;
- repeated imports produce byte-identical Canonical/evidence dumps where captured.

## Closure evidence

Supported C# loop shapes must reach the existing Core backend and execute correctly on
the compatible ISE. Compilation-only evidence is insufficient for advertised loop
semantics.

## Release disposition

Profile-gated. No general managed calls are enabled until Phase 2/3.
