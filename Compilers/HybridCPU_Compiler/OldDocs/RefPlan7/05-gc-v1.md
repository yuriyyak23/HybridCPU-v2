# Phase 5 — GC V1: precise single-thread STW non-moving mark-sweep

## Goal

Deliver the first correct collector with minimal cross-layer complexity.

## Prerequisites

Final frame lowering and code-manager/stack-walk contracts are proven; object/array/boxed GC maps, static roots, allocator and supported byref/interior policy are closed.

## Design decision

V1 is precise, stop-the-world, non-moving, non-generational and non-concurrent. Do not add a remembered-set write barrier unless a later collector design requires it.

This phase is explicitly **single-thread GC core**. Multi-thread suspension/rendezvous is Phase 11.

## Compiler ownership

- place safepoints at managed/runtime calls, allocation slow paths and loop backedges as required by policy;
- emit stack/root maps only from final scheduled/allocated/framed code;
- represent object roots and every admitted byref/interior root shape correctly;
- emit static roots and final-PC code-manager mappings;
- fail closed if a GC-capable site lacks complete metadata.

## Managed Runtime ownership

- heap enumeration, mark worklist, sweep/free-list;
- code-manager lookup and stack walking using compiler records;
- static roots;
- runtime-helper temporary roots;
- handle table and handle-root enumeration;
- explicit pinning semantics even though a non-moving V1 makes physical relocation unnecessary;
- deterministic collection threshold, root order, mark-worklist order and free-list order.

Kernel only owns execution-context coordination; for this single-context phase no MT rendezvous is required. ISE never parses stack maps or GC metadata.

## Root oracle tests

Keep the sole live object sequentially in: caller/callee-saved register, spill slot, static, object field, array element, handle, boxed/reference-bearing value, admitted byref/interior location, runtime helper temporary, delegate placeholder where available.

Add graph property tests for cycles, diamonds, self-reference, shared tails, unreachable cycles, large arrays, OOM/collection retry and corrupt-map fail-closed behavior.

## Closure

End-to-end allocation -> safepoint -> root enumeration -> collection -> continued execution runs through `.hcexe`, Managed Runtime and ISE. Final stack-map artifact digests are recorded in the phase evidence manifest.
