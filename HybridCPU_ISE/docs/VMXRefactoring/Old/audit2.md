## Вердикт

**Refactor нельзя считать завершённым, architectural freeze пока нельзя.** Текущий `master` сильно продвинулся по quarantine/fail-closed, но это скорее **current-model completion**, а не architectural closure: VMX-heavy frontend и legacy VMCS carrier в основном удалены/заперты, но generic substrate всё ещё частично VMX-shaped, а часть “generated/typed/projection” доказана контрактами и таблицами, а не реальным source-of-truth rewrite. Требуемая audit stance — не доверять словам `closed`, `generated`, `projection`, `descriptor-backed` без проверки кода — здесь критична. 

Главный класс оставшихся рисков: **axis regression risk** через compatibility mask ingress, nested enablement, memory translation identity, Lane6 token/queue state и future generated artifacts. Документ актуального snapshot сам признаёт transitional состояние: nested fail-closed до generic nested-domain service, grant-backed capability projection with remaining mask-ingress audit, NPT/VPID vocabulary и физическое размещение generic substrate под `Core/VMX/Substrate`.

Generic vector-stream execution remains owned by `VectorStreamDomainRuntime`. Remaining VMCSv2 scalar writes, `VmcsV2Blocks`, `VmxCheckpointImage`, dirty/checkpoint/vector DTO vocabulary, generator proof, nested-domain service, capability masks, translation vocabulary, and substrate-location risks stay open.

## Остаточные риски и незакрытые вопросы

1. **[authority/security risk reduced] `CapabilityDescriptorSet` is now grant-first, but compatibility mask ingress still needs caller audit.**
   `CapabilityDescriptorSet` no longer stores `GlobalHardwareCaps`, `RuntimeEnabledCaps`, or `DomainGrantedCaps` as backing authority. Those values, `CompatibilityCapsProjection`, and `EffectiveCaps` are now projections from `TypedGrants`. The remaining risk is not descriptor-local bitmap authority; it is callers that still seed compatibility masks or use non-typed capability requirements as admission/security shortcuts.
   Progress 2026-05-25 task `199`: active production admission/publication callers have been audited and changed so non-typed mask requirements fail closed. Descriptor-local projections remain grant-backed, and mask ingress is confined to compatibility seed materialization.

2. **[authority/security residual] Compatibility mask factories are now projection ingress, not descriptor source of truth.**
   `CapabilityGrantCollection.FromCompatibilityMasks(...)` creates stage grants for hardware/runtime/domain evidence and only creates guest-visible compatibility projection grants for bits that pass all stages. This removes the old effective-mask-as-authority cache from `CapabilityDescriptorSet`, but mask ingress remains an audit target until active production callers are either replaced with canonical grant collections or explicitly quarantined as compatibility seed paths.
   Progress 2026-05-25 task `199`: the active caller audit found no remaining production admission path that treats this compatibility factory as authority. It stays as a compatibility ingress only, with conformance checking that caller paths do not consume the masks as a security grant.

3. **[architecture smell] Runtime admission допускает non-typed path.**
   `CapabilityBoundaryRequirement` “prefers typed grants”, но если `RequiresTypedGrant == false`, проверка падает обратно на `descriptorSet.HasEffectiveCapability(...)`. Для freeze это опасно: один caller с `RequiresTypedGrant: false` возвращает mask-derived authority в security decision path. 
   Progress 2026-05-25 task `199`: this specific fallback is removed. Nonzero non-typed requirements now return false, and runtime authority/validation/admission receive the full typed requirement instead of checking a mask through `HasEffectiveCapability(...)`.

4. **[axis regression risk] Nested model всё ещё несёт VMX vocabulary внутри substrate.**
   `NestedEnablementRequest` имеет `PublishedVmxCaps`, `PublishedCapabilityWord`; `NestedDomainCapabilityProjection.VmxCompatibility` напрямую привязан к `VmxV2InstructionCaps.NestedVmx`; `NestedEnablementProof.FromCompatibilityMasks(...)` строит capability/gate proof из masks. Это лучше fail-closed, но generic nested-domain composition ещё не является источником истины.  
   Progress 2026-05-25 task `199`: `PublishedVmxCaps`, `PublishedCapabilityWord`, and `NestedEnablementProof.FromCompatibilityMasks(...)` are removed from production nested policy. Compatibility words are denied projection aliases, while publishable nested capability state comes from typed grants. Generic nested-domain composition is still not complete, so the broader nested service remains a freeze blocker.

5. **[axis regression risk] Shadow VMCS bridge удалён как active authority, но generic replacement не доказан.**
   `ShadowVmcsNestedProjectionService` теперь fail-closed, но сам класс всё ещё принимает `VmcsV2Descriptor` и прямо сообщает, что nested execution требует future generic nested-domain projection service. Это правильный quarantine/fail-closed результат, но не closure nested virtualization. 
   Progress 2026-05-25 task `203`: a neutral `NestedDomainProjectionCheckpointService` now combines generic projection admission with `DomainCheckpointImage` / `RestoreValidationService` validation and denies host-owned restore evidence. `ShadowVmcsNestedProjectionService` still accepts compatibility vocabulary only and fails closed; nested VMX execution is deliberately not enabled through it.
   Progress 2026-05-25 task `204`: the remaining nested child-intent compatibility identity aliases are removed from the substrate surface. `ChildDomainIntentDescriptor` no longer publishes VMCS12 pointer vocabulary or VMREAD/VMWRITE helper names, and its default access ids no longer import `VmcsField.Vpid`; neutral child-intent ids describe address-space and second-stage fields instead.

6. **[axis regression risk] Memory translation всё ещё имеет VMX/NPT/VPID-shaped canonical carrier.**
   Даже после появления `MemoryDomainTranslationControl`, active `MemoryTranslationControl` содержит `NptEnabled`, `VpidEnabled`, `GuestCr3`, `NptRoot`, `Vmid`, `Vpid`, `VmcsIdentity`, `VmcsEpoch`. `FromDomainControl(...)` возвращает compatibility-shaped control, а `ToAddressSpaceId(...)` всё ещё заполняет VMID/VPID/NPT-root-based identity. Это нельзя считать VMX-decentered memory substrate. 
   Progress 2026-05-25 task `200`: `MemoryTranslationControl` remains compiled compatibility vocabulary, but its `ToAddressSpaceId(...)` now delegates to `DomainControl.ToAddressSpaceId(...)`; live page-walk and domain-bound IOMMU consumers operate on `MemoryDomainTranslationControl` after compatibility ingress. The compatibility record itself is deliberately retained as residual projection work, not claimed as neutralized.
   Progress 2026-05-25 task `201`: active domain-bound IOMMU APIs now accept `MemoryDomainTranslationControl` directly, and dead compatibility conversion/factory helpers (`CreateSecondStageControl`, `CreateRuntimeProjection`, `FromDomainControl`, `ToCompatibilityControl`) are absent. `MemoryTranslationControl` survives only as frozen read-side vocabulary and is not an executable authority source.

7. **[axis regression risk] `AddressSpaceId` прямо описан как “VMX nested-translation address-space identity”.**
   Поля `Vmid`, `Vpid`, `NptRootIdentity`, `EptEpoch`, `VpidEpoch` остаются в TLB/NPT cache identity. Даже если это “runtime-owned evidence”, для HybridCPU это architectural smell: canonical address-space tags должны быть domain/address-space/second-stage epoch, а VMX/EPT/VPID должны быть только projection aliases. 
   Progress 2026-05-25 task `200`: this specific risk is closed for canonical address-space/TLB identity. `AddressSpaceId`, `NestedTlbTag`, and `TLB` now use only neutral domain/address-space/second-stage tags and epochs, guarded by `AddressSpaceCanonicalIdentityAuthorityRemovalContract`.

8. **[axis regression risk] Nested memory composition всё ещё NPT/VPID-centered.**
   `NestedMemoryCompositionContext` принимает `MemoryTranslationControl` для child/host, содержит `L2Vpid`, строит `AddressSpaceId` через `HostTranslationControl.Vmid`, `L2Vpid`, composite NPT root, EPT/VPID epochs; service exposes `InvalidateByNestedVpid` and `InvalidateByCompositeRoot`. Это не generic second-stage composition closure. 
   Progress 2026-05-25 task `200`: active composition context now takes `MemoryDomainTranslationControl`, uses `ChildAddressSpaceTag`, and exposes `InvalidateByAddressSpaceTag` / `InvalidateBySecondStageRoot`; its raw walk helper was renamed and routed as second-stage translation. Generic nested projection/checkpoint ownership remains incomplete.
   Progress 2026-05-25 task `201`: canonical translation results no longer expose `NptViolation`, `NptMisconfiguration`, or `CausesVmExit`; nested fault routing reads second-stage faults. The unreferenced `ComposedDomainProjectionComposer` containing host VMCS-shaped projection identity was removed without replacement. A real generic nested projection/checkpoint service remains unimplemented and therefore remains a freeze blocker.
   Progress 2026-05-25 task `203`: the neutral nested projection/checkpoint admission owner now exists outside `Core/VMX`; it validates descriptor-approved projection and domain-owned checkpoint restore together. Runtime enablement/publication wiring remains fail-closed and separate from this closed ownership boundary.

9. **[evidence leak risk / migration blocker] Lane6 остаётся самым слабым местом.**
   `Lane6StateBlock` напрямую владеет `VmxLane6QueueVirtualizer`, принимает `IommuDomainBinding`, мапит `DmaStreamComputeTokenHandle hostHandle`, и имеет `TryResolveHostToken(...)`. Это активный runtime path, где host-owned token evidence находится рядом с guest-visible virtual token namespace. Для freeze нужно доказать, что это не попадает в migration/checkpoint/guest projection. Сейчас это не доказано. 
   Progress 2026-05-25 task `202`: `Lane6StateBlock` now delegates native-token binding to neutral `Lane6HostOwnedEvidenceStore`; the active VMX-shaped queue/token carrier is absent, restore drops host bindings and requires rebuild, and conformance links the runtime test to the migration/checkpoint native-token rejection policy.

10. **[evidence leak risk] `VmxLane6QueueVirtualizer` хранит host tokens в `_hostTokens`.**
    Внутри `NonRTL/Core/Execution/DmaStreamCompute/VmxLane6QueueVirtualizer.cs` есть `_hostTokens: Dictionary<Lane6VirtualToken, DmaStreamComputeTokenHandle>`, а queue/token keys построены на `Vmid/DomainId/DeviceId`. Плюс epoch advance использует wrap-to-1, не fail-closed. Это одновременно host evidence leak surface и stale-token/epoch collision risk. 
    Progress 2026-05-25 task `201`: queue/token identity is now neutralized to `IoDomainTag` / `DomainId` / `DeviceId`; `_hostTokens`, class placement/naming, epoch policy, and migration rebuild proof are intentionally not claimed closed.
    Progress 2026-05-25 task `202`: this specific carrier is removed. `_hostTokens` does not survive in production; host mappings live only in neutral host-owned evidence storage, and `TryAdvanceEpoch` returns `DmaFaultKind.EpochExhausted` at exhaustion without wrap-to-1 reuse.

11. **[authority/security risk] DMA/IOMMU лучше fenced, но не fully neutral.**
    `DmaAuthorityService` уже требует `IoDomainDescriptor`, DMA window, valid binding, permissions, fence; но binding type всё ещё `IommuDomainBinding`, а сам binding содержит `Vmid`. Это частично закрыто contract-wise, но IO/DMA identity ещё не очищена до generic IO-domain tag.  
    Progress 2026-05-25 task `201`: executable `IommuDomainBinding`, `IotlbTag`, `IoVirtualizationBlock`, IOTLB invalidation, DMA admission evidence, and host IOMMU binding now use `IoDomainTag` or `IoDomain` identity. Frozen VMX IOTLB alias entry points only delegate to neutral operations.

12. **[generator closure proven for current executable-lineage claims] VMCS field schema, VmxCaps bit schema, compat aliases, and compat spec manifest now have build-time regenerated-output proof.**
    `VerifyVmxProjectionLineage` regenerates expected C# from the neutral JSON schemas and fails the build on drift before `CoreCompile`. The remaining risk is no longer self-reported generation for these artifacts; it is semantic source-of-truth ownership and any future artifact that wants to claim executable generated lineage.

13. **[generator closure proven for VmxCaps bit metadata] Pipeline contract no longer only self-reports for VmxCaps.**
    `ProjectionSchemaPipelineContract` remains metadata/conformance, but the build now executes a verifier for `VmcsFieldProjectionSchema`, `CompatAliasMap`, `CapabilityDescriptorSetSchema`, and `CompatSpecArtifactSet`.

14. **[long-term maintainability risk reduced] `CompatSpecArtifactSet` is now generated and distinguishes executable lineage from projection-only vocabulary.**
    `CompatSpecArtifactSet` is regenerated from `compat-spec-artifact-schema.v1.json`. `VmcsFieldAliases`, `CapabilityProjection`, and `CompatAliasMap` require executable generated lineage; `CompletionProjectionService` is explicitly `ProjectionContractOnly`, not a false generated-output claim. Remaining maintainability risk is semantic: future projection artifacts must be added to this manifest or be treated as contract-only.

15. **[conformance weakness] Static authority boundary lexical, не semantic.**
    `CoreVmxAuthorityBoundaryContract` ищет строки вроде `.ShadowVmcs.`, `IOMMU.`, `BindVmx`, `ReadFieldValue(`, `CsrAddresses.VmxCaps`. Это ловит obvious regressions, но не ловит semantic wrappers, renamed aliases, indirect authority через delegate/service, или VMX-shaped fields без forbidden marker. Это guardrail, не semantic proof. 

16. **[checkpoint/migration risk] Migration policy хорошая, но end-to-end rebuild не доказан.**
    `MigrationValidationPolicy` отвергает host-owned evidence и compatibility projection metadata, `DomainCheckpointImage` reject-ит host-owned evidence masks, `RestoreValidationService` reject-ит compatibility projection as authoritative state. Но это mask/policy validation, а не доказательство, что Lane6 `_hostTokens`, TLB/IOTLB entries, backend handles и scheduler evidence не сериализуются через другой image path и rebuilt after restore.   
    Progress 2026-05-25 task `202`: Lane6 native token handles now have an executable rebuild-only proof: host bindings are cleared during restore preparation, native token evidence is rejected by checkpoint policy, and a fresh host handle must be rebound after restore. Other backend/scheduler evidence families remain separate residual review.

17. **[axis regression risk] Current VMX opcode semantics фактически fail-closed, не admitted generic operations.**
    Snapshot говорит, что VMX opcode routing остаётся typed fail-closed, а VMCALL/VMFUNC/VMLAUNCH/VMRESUME/VMXON/VMXOFF и другие compatibility paths ждут generic runtime admission. Это правильно для security, но не freeze-ready compatibility frontend: ABI frozen, execution model not yet projected/admitted/retired through generic domain operations. 

18. **[long-term maintainability risk] Generic substrate всё ещё физически живёт под `Core/VMX/Substrate`.**
    Документ прямо отмечает: новый `Core/Runtime` — только first extraction foothold; substrate remains mostly under `Core/VMX/Substrate`. Это не immediate leak, но перед architectural freeze важно не закрепить VMX as directory/namespace owner for generic domain/capability/evidence/runtime substrate. 
    Progress 2026-05-25 task `205`: one concrete extraction foothold is now closed for Lane7 host-owned evidence: native token maps, backend binding cache, and scheduler pressure cache live under `Core/Runtime/Lanes/Lane7/HostOwnedEvidence`. The broader physical relocation of remaining generic descriptors and substrate files is still open.
    Progress 2026-05-25 task `206`: one domain-runtime foothold is now closed too: domain context/operation/authority/root/legality/validation/scheduling/binding services live under `Core/Runtime/Domains/*`, and the old `Core/VMX/Substrate/Runtime/*` copies are absent. This reduces, but does not finish, physical substrate relocation.
    Progress 2026-05-25 task `207`: the generic descriptor/admission foothold is also reduced: most non-capability domain descriptors, domain admission runtimes, and neutral nested projection primitives now live under `Core/Runtime/Domains/*` or `Core/Runtime/Nested/*`. Remaining physical relocation blockers are capability generated projection/schema placement, memory translation/checkpoint services, I/O/DMA services, lane state blocks, completion/event services, and explicit compatibility projection surfaces.

## Blockers перед architectural freeze

1. **Finish capability caller cleanup outside `CapabilityDescriptorSet`.**
   Progress 2026-05-25 task `198`: `CapabilityDescriptorSet` now accepts a canonical `CapabilityGrantCollection` as source of truth, and its bitmap-like properties are read-only projections over typed grants. Before freeze, active production callers still need audit so `FromCompatibilityMasks(...)`, `PublishedVmxCaps`, `PublishedCapabilityWord`, and non-typed `HasEffectiveCapability(...)` fallback paths cannot become security/admission authority.
   Progress 2026-05-25 task `199`: this blocker is closed for current active production callers. Keep it as a regression guard: new callers must not reintroduce compatibility masks as admission/security authority.

2. **Сделать generated projection реально generated.**
   Progress 2026-05-25 tasks `196` and `197`: build-time regeneration/drift check covers `VmcsFieldProjectionSchema`, `CompatAliasMap`, `CapabilityDescriptorSetSchema`, and `CompatSpecArtifactSet`. New artifacts that claim executable generated lineage must join this verifier; projection-only surfaces must remain explicitly contract-only.

3. **Вынести memory identity из VMX/NPT/VPID naming.**
   `AddressSpaceId`, `MemoryTranslationControl`, `NestedMemoryCompositionContext`, TLB/IOTLB invalidation должны перейти на `DomainTag`, `AddressSpaceTag`, `SecondStageRoot`, `SecondStageEpoch`, `AddressSpaceGeneration`, без `Vmid/Vpid/Npt/Ept/VmcsEpoch` как canonical fields.
